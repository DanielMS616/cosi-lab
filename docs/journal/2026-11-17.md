# 2026-11-17

## GPT und Gemini über den SSH-Tunnel vollständig geprüft

Ich habe im Mac-Browser über den SSH-Tunnel dieselbe Dokufrage an GPT und Gemini gestellt: 
„Welche CPU ist verbaut und wie läuft SSH im WireGuard-Tunnel?“ Dabei war die Suche mit zwei Quellen aktiviert.

Der erste GPT-Versuch scheiterte vor dem Modellaufruf, weil der API-Schlüssel auf Cosi-Lab fehlte. 
Nach der lokalen Konfiguration und dem Neustart von Uvicorn wurde die GPT-Antwort als Dokulauf `1` gespeichert, 
die Gemini-Antwort als Dokulauf `2`. Beide Antworten belegten den Intel Core i5-8500 mit 6 Kernen und die SSH-Anmeldung 
mit Schlüssel durch die jeweils passende Quelle.

Nach dem Neuladen konnte ich beide Läufe aus der Historie öffnen. 
Antwort, ursprünglicher Prompt und beide gespeicherten Quellenausschnitte wurden wieder angezeigt. 
Damit ist der Ablauf vom Browser über Cosi-Lab bis zur Speicherung und zum erneuten Abruf 
in SQLite für beide Anbieter praktisch geprüft.

## Cosi-Lab mit Docker Compose gestartet und SQLite geprüft

Ich habe den manuellen Uvicorn-Start durch `docker compose` ersetzt. Die Datei `compose.yaml` beschreibt, 
wie der Dienst `api` gebaut und gestartet wird. Sie bindet den vorhandenen Projektordner `./data` 
vom Ubuntu-Rechner unter `/app/data` im Container ein. Dadurch arbeitet die API mit derselben SQLite-Datei wie vorher. 
Über `COSI_UID` und `COSI_GID` läuft sie mit meiner Ubuntu-Benutzer- und Gruppen-ID, 
damit sie die vorhandenen Laufdaten lesen und neue Läufe schreiben kann. 
Die API-Schlüssel werden erst beim Start aus der lokalen `.env` übergeben.

Ich konnte die vorhandenen Dokuläufe `1` und `2` aus dem Container abrufen. 
Danach stellte ich im Mac-Browser über den SSH-Tunnel die Frage „Welche CPU hat Cosi-Lab?“ an GPT. 
Die Antwort zum Intel Core i5-8500 wurde als Dokulauf `3` mit Status `completed` gespeichert. 
Auf Cosi-Lab las ich den Lauf anschließend mit `show_doc_run.py` direkt aus SQLite. 
Der gespeicherte Prompt, der Quellenausschnitt, die Antwort und die Zitatprüfung wurden angezeigt.

### 1. Die API auf Cosi-Lab starten

Beim Zugriff von unterwegs aktiviere ich auf dem Mac zuerst WireGuard. Dann melde ich mich in einem Mac-Terminal an:

```bash
ssh cosi-vpn
```

In dieser **SSH-Sitzung auf Cosi-Lab**:

```bash
cd ~/cosi-lab-lernversion
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
```

Voraussetzung ist, dass die lokale `.env` und `data/model_runs.sqlite3` auf Cosi-Lab vorhanden sind. 
Auf einem neu eingerichteten Rechner ermittle ich die Werte für `COSI_UID` und `COSI_GID` mit `id -u` und `id -g`. 
Falls noch ein manuell gestarteter Uvicorn-Prozess Port `8000` belegt, beende ich ihn vor `docker compose up`.

Mit `-d` läuft die API im Hintergrund. 
Falls der erste Abruf zu früh kommt, schaue ich ins Serverlog und warte auf `Application startup complete`:

```bash
sudo docker compose logs --tail=30 api
curl -i 'http://127.0.0.1:8000/doc-runs?limit=3'
```

Nach dem dokumentierten Test enthielt die Liste die IDs `3`, `2` und `1`. 
Dieser Abruf prüft die API und die Datenbank direkt auf Cosi-Lab, unabhängig vom Mac-Browser.

### 2. Den SSH-Tunnel vom Mac öffnen

In einem **zweiten, lokalen Mac-Terminal** starte ich den Tunnel und lasse das Terminal offen:

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:8001:127.0.0.1:8000 cosi-vpn
```

Der Mac-Port `8001` leitet zum lokalen Port `8000` auf Cosi-Lab weiter. 
Wird das Tunnelterminal geschlossen, läuft der Container weiter, 
aber der Mac-Browser erreicht ihn erst wieder nach einem erneuten Tunnelstart.

### 3. Den Lauf im Browser und im Terminal zeigen

Im Browser öffne ich [http://127.0.0.1:8001/](http://127.0.0.1:8001/) und wähle unter **Letzte Dokuläufe** die ID `3`. 
So kann ich die Antwort zusammen mit dem gespeicherten Prompt und der ursprünglichen Fundstelle zeigen.

In der SSH-Sitzung auf Cosi-Lab kann ich denselben Lauf unabhängig vom Browser direkt aus SQLite lesen:

```bash
.venv/bin/python show_doc_run.py 3
```

Für diese Vorführung reicht der gespeicherte Lauf. 
Ein neuer Modellaufruf ist nur nötig, wenn ich das Schreiben eines weiteren Laufs live zeigen möchte.
